# 2026-09-14 浏览器安全加固

## 目标

收紧可见 Chrome/CDP 的本机访问边界，防止采集器误用日常 Chrome profile，并降低浏览器 Network 探针泄露 POST 请求体的风险。

## 实际操作

- `ChromeCdpConfig` 只接受 `localhost` 或 `127.0.0.0/8`，并将 `localhost` 归一化为 `127.0.0.1`。非本机地址、主机名和 IPv6 地址会在启动 Chrome 前被拒绝。
- Chrome 启动前会解析 profile 真实路径，拒绝 macOS、Linux 和 Windows 常见日常 Chrome/Chromium 用户数据目录及其子目录。POSIX 系统同时参照环境 home 和系统账号目录，避免 `HOME` 被覆盖后绕过。`profile_name` 只允许单个普通目录名，最终 profile 路径通过软链接指向日常目录时也会被拒绝。
- CDP 统一使用 `--remote-debugging-port=0` 由 Chrome 自动分配端口。采集器从专用 profile 新写入的 `DevToolsActivePort` 读取端口和浏览器路径，并与 `/json/version` 的 WebSocket 路径交叉校验。任何非零固定端口配置都会被拒绝。
- `discovery.inspect_browser` 默认只记录 POST 请求体是否存在和 UTF-8 字节数，并遮蔽 URL 中常见敏感查询参数。仅显式传入 `--show-post-data` 时输出原始请求体。
- README 补充 CDP 回环限制、专用 profile 要求和探针原始请求体开关的风险说明。

## 验证结果

- 使用独立临时 profile 启动真实 Google Chrome，通过 CDP 访问 `https://example.com`：调试主机归一化为 `127.0.0.1`，Chrome 自动分配的端口和浏览器路径均与 `DevToolsActivePort` 匹配，HTTP 状态为 200，页面标题和 DOM 正常。同一专用 profile 连续启动两次均正常，未读取上次残留端口。
- 会话关闭后未发现残留测试 Chrome 进程，临时 profile 已移入废纸篓。
- `.venv/bin/python -m unittest discover -s tests -v`：82 项通过，包含旧 `DevToolsActivePort`、畸形/越界端口和 WebSocket browser path 不匹配的安全失败分支。
- `.venv/bin/python -m compileall -q common collectors discovery tests`：通过。
- `git diff --check`：通过。
